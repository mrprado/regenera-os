# Regenera OS audit against the master specification (2026-09-24)

Steps 1–4 of the master spec (docs/master-spec.md): audit, current-state architecture, feature map, duplication.
The target schema, migrations, integrations, regulatory, contracts, navigation and phased plan are in
docs/plans/phase-6.md.

## 1. Current-state architecture

| Layer | What exists |
|---|---|
| Runtime | Next 16 App Router + React 19 built with vinext, one Cloudflare Worker `regenera-os` at regenera.bio/os (routes in front of the public site's Custom Domain; basePath `/os`). 5-minute cron runs the job tick. |
| Data | Cloudflare D1 (SQLite), Drizzle ORM, 10 migrations (0000–0009), 58 tables. R2 bound in code but **not enabled** on the account. |
| Auth | Email + password (tracker password or `OS_PASSWORD`), D1 sessions, allowlist bootstrap. No lockout (off at Prado's request). |
| Authorization | Mandate scoping on every query (`lib/db/scoped.ts`), roles `owner` / `member` per mandate, header mandate switcher. Route-guard test enforces a guard on every page, API route and server action. |
| Jobs | D1 `jobs` table + tick; 33 job types; cadence grammar (`every:`, `daily:`, `weekly:`, `monthly:`); budget and retry handling. |
| AI | Claude via `runStructured`/`runAgent`, prompts versioned in D1, every call logged to `ai_runs` with cost; Ask the OS (Cmd+K) with confirm-before-write proposals; MCP server with OAuth; monthly learning loop. **No Anthropic key set yet**, so AI features are idle. |
| External data | `lib/sources/*` with limits, cache (`source_cache`) and ledger (`provider_calls`): GLEIF, SEC EDGAR (CIK, Form D), Wikidata, GDELT, GDACS, TED, World Bank procurement, Grants.gov, EU Funding & Tenders, UK Contracts Finder, Nominatim, Apollo (free tier), SBTi and TNFD lists; NASA Blue Marble and Esri basemaps. |
| Deployment | `npm run deploy` (build, D1 migrations, deploy). No staging. No git remote. |
| Blocking | Workers Free plan: signed-in pages exceed the 10 ms CPU limit (error 1102) until Workers Paid. Secrets for jobs not set. |

**Main flows today:** triggers and lists → people and companies → sequences and approval queue → sending, replies,
calendar → deals (board) → contracts; funding scans → bids (deals) and applicant matches; reports, forecast,
learning loop, daily digest.

## 3. Duplication and consolidation

1. **"Mandate" means two things.** In the code, `mandates` are Regenera's books of business (Regenera, RA-ESG, GWCe)
   that scope all data. In the spec, CapitalMandate is an investor's investment mandate. Proposal: keep the table,
   call it **Entity** in the interface ("Regenera", "RA-ESG", "GWCe"), and use `capital_mandates` for the spec's
   meaning.
2. **Deals do three jobs**: sales opportunity, engagement and stand-in for a project. Proposal: keep deals as
   **Opportunities** (Regenera's commercial pipeline) and add **Projects** as the physical asset; a deal links to a
   project.
3. **Three list concepts**: `segments` (playbooks), `saved_searches` (Apollo searches) and `lists` (manual and
   public lists). Keep, but present under Prospecting only; consolidate later.
4. **Partners** duplicate organizations. The Partner Network record should become a role of an organization
   (introducer) plus the referral agreement contract.
5. **Payment milestones** become one kind of contract obligation.
6. **`/searches`** is a leftover redirect page; remove it.
7. **TED and World Bank** feed both signals and funding; already de-duplicated by disabling their trigger queries.

## 4. Conflicts with the stack and constraints

- **PostgreSQL/PostGIS (Part XV):** the OS runs on D1 (SQLite), and CLAUDE.md forbids Supabase and requires asking
  before stack changes. The spec says PostGIS "where compatible". Proposal: GeoJSON stored in D1 with bounding-box
  columns for indexing; point-in-polygon and distance checks in the Worker. Revisit only if spatial analysis outgrows
  it (then a managed Postgres, which is a paid service decision for Prado).
- **Heavy compute** (economics scenarios, place profiles from rasters, EPD comparisons) needs Workers Paid CPU at
  minimum; raster processing stays with the source APIs (NASA POWER, Copernicus) rather than in the Worker.
- **File storage** (documents, executed contracts, evidence) needs R2 enabled.
- **Licensed data** (IBAT, Protected Planet commercial, OpenCorporates, Open-Meteo commercial, EC3 terms) stays
  behind the license flag.

## 5. Should not be built yet

Engineering, materials/EPD/BoQ/circularity, construction and operations control tower, economics and scenario
modelling, procurement pipeline, insurance and tax modules, external portals, KYC provider integration, Copernicus
and other raster sources, structured natural-language search beyond what Ask the OS already does. Each depends on
Projects, Documents and real project data first.

## 6. Verdict

The OS is strong on **origination, outreach, intelligence and funding discovery**, with good discipline on scoping,
approvals, provenance of identity fields and audit. It is missing the **project spine** that the whole spec hangs
from (Project, readiness, constraints, capital requirements, tranches), the **capital side** (capital and private
capital profiles, qualifications, capital opportunities, commitment ledger, compliance gate for investment
communications), and **general contracts, obligations and documents**. The next work should add those spines and
connect existing records to them, not rebuild the interface.
